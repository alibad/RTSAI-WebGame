# Public browser release: 15 October 2026, less garbage per tick

The owner: "let's do 1 and 4", that is, one scripted, checked release for /play and less garbage during play; then
"yes push all and deploy". This is the first release made with `tools/release-play.mjs`.

## What players get

Play makes less garbage, so the worker pauses less often to collect it, and the tab spends less CPU. Each figure below
is 20 seconds of play in the browser, using the same page and data with only the runtime changed. In both the
skirmish and the battle, the camera was on the player's units.
- Skirmish: 11.2 MB/s before, 5.0 MB/s after.
- Original-art battle: 15 MB/s before, 13 MB/s after.

How it was done is in [PERFORMANCE.md](PERFORMANCE.md) under "Garbage per tick". Nothing else changes: no new
features, the simulation is unchanged, and the data is unchanged.

## Checks

- **Smoke test** (`tools/release-smoke.mjs`), with the page on the Cloudflare roots and no sign-in gate.
  - It played: an isometric skirmish, the original-art battle, the skirmish twice more, and the Classic skirmish.
  - Every match started, ticked and drew.
  - The repeated skirmish left 42 textures after quitting both times, and WebAssembly memory stayed at 478 MB both
    times.
  - Nothing threw.
- **Native allocation measurement** (the harness in `D:\rtsai-perf\alloc`): skirmish 0.297 → 0.041 MB per tick. The
  UI state, catalog, coach and ground vertices were unchanged in every comparison. Battle sync hashes were unchanged
  with the engine change.
- **Dry runs.** These were full dry runs: the same build and smoke test, with nothing deployed.
  - The first, on main before the map editor, caught the live campaign page `efba68d` while it was not yet on main.
    The campaign session pushed it soon after.
  - The rest caught three changes on main that the release flow had to follow:
    - the page now compiles RTSAI-Web, so the tool keeps its own checkout of that repository at its `origin/main`;
    - a new web dependency, so the tool runs `npm ci` whenever `package-lock.json` changes;
    - the editor's new mod inputs.

## Not in this release
