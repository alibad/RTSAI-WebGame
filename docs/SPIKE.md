# RTS AI web engine spike (October 2026)

The real OpenRA simulation (engine `rtsai/web-engine` + RTSAI-Mod `main`, C# unchanged) compiled to .NET
WebAssembly, ticking at 25 tps in a Web Worker, drawn with WebGL2 from the engine's own sprite sheets and palette.

## Architecture

```
page (main thread)                          worker (.NET 10 browser-wasm, interpreter or AOT)
  React HUD  ── input ──postMessage──▶  Interop [JSExport]
  WebGL2: terrain VB + instanced          └─ SimHost: OpenRA.Game + Mods.Common/Cnc + RA2 + RTSAI
          SpriteRenderables (lerp 60 fps)       World.Tick ◀─ OrderManager ◀─ WebConnection (records packets + SyncHash)
          ◀── SharedArrayBuffer ring ───────── Snapshot: actors + every SpriteRenderable + new sprites/strings
          ◀── sheets/palette (transfer) ─────── WebPlatform (headless IPlatform that keeps texture bytes)
```

* Orders: right-click goes through the engine's own `UnitOrderGenerator.Order` (same orders as the desktop game),
  `world.IssueOrder`, then the next tick. Cursor names come from `UnitOrderGenerator.GetCursor`.
* Drawing: the snapshot carries the exact `SpriteRenderable`s the engine produces (`actor.Render`, effects),
  sorted with the engine's z key; the shader is a port of `glsl/combined.*` (channel masks, hardware palette,
  depth). Terrain is the engine's `TerrainSpriteLayer` vertex buffer, unchanged.
* VFS: `data/web-bundle.pack` (mod + engine `mods/common`, no EA files) is unpacked into MEMFS. LOCAL/admin only:
  the player's own RA2 packages (`%LOCALAPPDATA%\RTSAI-WebGame\private\ra2-all.pack`) are served by the dev server to
  loopback clients and mounted at `support/Content/ra2`. Never bundled, committed or deployed.

## Engine changes (`OpenRA-wt-web`, branch `rtsai/web-engine`)

* `Log` writes synchronously in the browser (no threads); `ObjectCreator` resolves mod assemblies by name;
  `MapCache` skips FileSystemWatcher in the browser; `Ruleset` loads synchronously in the browser (the load-screen
  Task + `Wait(40)` loop spins forever on a single thread); `SpriteRenderable` exposes Sprite/Origin/Scale/Rotation;
  `InternalsVisibleTo OpenRA.WebSim`.

## Web mod.yaml (generated by `websim pack`)

Drops `rules/companion.yaml` (gRPC sidecar), uses `WebLoadScreen`, adds `OpenRA.WebSim.dll` and
`web/web-rules.yaml` (no in-game widget root, plus a `webidle` bot seat). Unit, weapon and economy rules unchanged.

## Run it

```
powershell tools\native.ps1                     # native build + bundle + native VFS
websim extract-content ... --out %LOCALAPPDATA%\RTSAI-WebGame\private\ra2-all.pack   # once, local only
dotnet publish sim\OpenRA.WebSim.Browser -c Release -o data\wasm-interp            # user-local SDK with wasm-tools
dotnet publish sim\OpenRA.WebSim.Browser -c Release -p:Aot=true -o data\wasm-aot
cd web && npm run build && cd .. && node server\serve.mjs                           # http://127.0.0.1:3490/?runtime=aot
node tools\fidelity.mjs --scenario scenarios\battle-200.json --ticks 1500 --runtime aot
node tools\measure.mjs --runtime aot --scenario battle-200 --verify
```

## Blockers

1. Content: terrain, infantry, buildings, effects come from the player's RA2 files. Public build must use the
   rtsai/standalone content (no EA files).
2. Interpreter is too slow at 200 units and to load (18 s): AOT only (6 min build, +4 MB download).
3. Memory: 620-870 MB wasm heap that never shrinks (MEMFS copy of the 256 MB pack, ~250-380 MB managed).
4. No game UI: sidebar/build queue/minimap/power/money, shroud and fog, voxels/beams/lines, audio.
5. Single-threaded wasm: any engine Task.Run + Wait path deadlocks (Ruleset fixed); UI/network paths unexercised.
6. Engine branch rtsai/web-engine is local only; companion AI (gRPC) dropped; only desktop Chromium tested.

## Phased plan

1. Standalone web build: standalone content, AOT, pre-baked sheets cached in the browser, lazy mounts.
   Targets: world start under 3 s, download under 30 MB, heap under 500 MB. Push the engine branch.
2. Playable skirmish: React sidebar and production through engine orders, minimap, shroud/fog, remaining
   renderables, WebAudio, hotkeys and control groups. fidelity.mjs nightly as the regression gate.
3. AI and online: hosted/companion AI over WebSocket; lockstep multiplayer relay (parity makes desktop
   cross-play possible); replays.
4. Ship: COOP/COEP hosting, CDN, Safari/Firefox/mobile matrix, performance budget gates.
