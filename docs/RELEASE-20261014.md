# Public browser release — 14 October 2026: random maps and forests

The owner asked for cliffs and water in the map generator, then "why don't you add forests and deploy". The release is
live at https://rtsai.net/play/ and https://rtsai-play.vercel.app/.

## What players get

- **New random map** in Skirmish, first in the map strip. The engine's own map generator (OpenRA's TSMapGenerator, set
  up for our temperate tileset in RTSAI-Mod `rules/map-generators.yaml`) makes the map in the player's browser in about
  2–3 seconds, with nothing uploaded or fetched. A landscape is picked from the seed: lakes, ponds, plains, parkland,
  woodlands, rocky hills, mountain lakes or mountains. The maps have cliffs, beaches, water, forests, ore fields around
  ore mines, and start positions for everyone in the match (96 cells a side for 2 players, 128 for 3–4). A seed whose
  layout cannot fit every start position moves on to the next seed.
- **Project trees** (RTSAI-Mod `tools/standalone-terrain.py --trees`): ten Blender-rendered variants shared by
  tree01–tree28. They replace the placeholder squares and the four flat circle trees in campaign maps.
- **Previews for the Web Arena maps**: maps without a picture get one drawn by the engine (`SetupInfo.Preview`).

## Not in this release

- Villages: civilian houses are still placeholders, so the generator places none.
- Random maps in multiplayer. The generator is deterministic, so sharing the seed could give every player the same map.

## Hotfix: the runtime identity (same day)

The release skipped `node tools/stamp-runtime.mjs` on the published runtime, so `rt-0299905b7541/` had no
`runtime-identity.json` and Cloudflare answered that path with its placeholder page. Multiplayer and saves fingerprint
the build with that file. About an hour after the release, the stamped file (identity `4e849f22…`, brotli like the rest
of the root) went into both profiles of the root, and Cloudflare was redeployed (`a8fcf71a`). Browsers that tried
multiplayer in that hour may keep the placeholder (immutable caching) and see "different game versions" until their
cache clears. The release steps now stamp the runtime right after publishing, as `docs/BROWSER-MODES.md` says.

## Random maps in multiplayer (second update, same day)

The owner asked for random maps in multiplayer, then "ship it".

- **What changed.** The lobby carries the request that made a random map, and each guest's browser makes the same map
  from it. The host gets "New random map" in the lobby. The order preview card no longer hides under the co-commander's
  orders between 900 and 1320 px wide.
- **Two generator fixes**, both in `MapGen.cs`:
  - The preview's colours come from the seed. The map uid hashes the preview, so random colours gave each browser a
    different uid for the same map.
  - A layout with fewer start positions than players retries the next seed. Seed 2002183150 made a two-player map
    with one spawn, and the world could not be created; this affected single-player skirmish too. 61 random
    two-player and 24 four-player maps now all start a world (11 of the 61 needed a retry).
- **Composition.** The page is the live page `bbecb68` plus these commits (branch `release/web-20261014b`, `9debbe5`;
  `25377fb` was not live and is not included). The runtime is the live runtime's source (`c4a3e93`) plus `MapGen.cs`
  only; the engine changes of `d4c85fd` on main are not in it, as before. Runtime root `rt-08958508163b/` (identity
  `32964cf7…`, stamped); the data root `data-169d5132ea83/` is unchanged.
- **Deployment.** Cloudflare `rtsai-play-cdn` (`105b16e6`; the older roots stay). Vercel preview
